# Changelog

This project is a fork of [briankwest/swdialer](https://github.com/briankwest/swdialer). The entries below describe how it diverges from upstream, newest first. For what the app does and how to run it, see the [README](README.md).

- **Layout fixes for tablets, small phones and 1024px windows** — on tablets in portrait the top bar's labeled buttons were drawn over the connection status and the signed-in subscriber; the tablet column is now wide enough for all of them. In a 1024px desktop window the Call button was cut off and the number on the call card wrapped mid-number; the middle column now keeps a minimum width. Opening the in-call keypad on shorter screens pushed Mute and End off the bottom; they now stay on screen at every size, and on phones up to 800px tall the open keypad trims the toolbar to Mute, Keypad, Speaker and End, sized so all four rows of keys fit. Landscape phones show the call status beside the keypad and the controls in one row. The call controls form an even grid with End always last. The address type ("Phone number") has its own line under the field instead of being cut to "PHO…", and the From/Video/Call row stays right-aligned on 320px phones. The Destinations tabs fit on one line in every desktop window and in the 320px phone panel, instead of wrapping or cutting off "Subscribers". Tests: the screenshot run adds tablet portrait (768×1024) and tablet landscape (1024×768).
- **Smaller fixes** — calling a subscriber whose browser is closed or in Do Not Disturb now says so instead of "Couldn't start the call.", and a call that times out while being set up gets its own message; browser-to-browser callers show the subscriber's name instead of `subscriber://<name>`; one tap on Delete removes one character (touch screens removed two); the call and incoming-call screens format numbers as `+1 (555) 123-4567`; subscriber tokens are requested with the documented `expire_at` expiry; and the backend's dial log keeps a number typed with a leading `+` as dialed instead of prefixing `1` to a 10-digit one.
- **Caller ID picker** — a **From** button beside Video opens a sheet listing what SignalWire accepts as the caller ID of a call to a phone number: the space's own phone numbers and its verified caller IDs (no free-text entry), with Default leaving the choice to the server. The number is passed to `dial()` as `from` (the invite's `caller_id_number`) for phone numbers only — the button is disabled for SIP URIs and Fabric addresses, and the service drops the value for them regardless — the choice is remembered across reloads, the call card shows the number that was sent, the event log's Dialing line carries it, and the backend's dial log receives it. A new gated `GET /api/caller-ids` merges the two Relay REST listings (the API token now needs the **Numbers** scope as well as Voice; a source that fails is named in the response and the other still lists). Tests: the dialer spec covers picking, the phone-number-only lockout, persistence, the error and partial states and the 320px layout; the desktop spec checks the sheet hands focus back to the address field; the backend suite covers the merge, trimming, the unverified filter, caching and the failure modes.
- **The Video toggle says what it does** — for a Fabric address the toggle is the address's channel: turning it on writes `?channel=video` into the field and turning it off writes `?channel=audio`, so the field is exactly what is dialed, and typing or pasting an address that names a channel sets the toggle to match. Phone numbers can't do video, so the toggle is disabled there; for a SIP URI it is the camera choice, and the dial now asks to receive video as well as send it. The type label under the field shows the channel, and Recents stores the dialed string. Previously the rewrite happened out of sight in the service, on every destination type (a phone number was dialed as `+1…?channel=video`) and only when the toggle was on, so a video address toggled off still negotiated receive-only video. Tests: the dialer spec covers the rewrite in both directions, typed channels, the phone lockout, the SIP choice and the picked label surviving a toggle.
- **Console layout; the phone metaphor is gone** — the UI is now a reference app rather than an iPhone: a top bar across every layout (the SignalWire wordmark, a connection pill that also shows Do Not Disturb, the signed-in subscriber as a chip, a sun/moon theme toggle; no clock), the address field with a **Video** toggle and a **Call** button under it, a flat keypad (always on phones, folded behind **Show keypad** in a desktop window, remembered), and in a call a card instead of an avatar: the status line, number, timer, call id (with copy) and quality badge on top, the remote video (with the local preview) or the DTMF pad in the middle, the level meters, and a toolbar that keeps every control in view — Mute, Keypad, Camera, Hold, Share, Speaker, More, End — on phones as well as desktop. Incoming calls are a card with Decline and Accept. From 1024px the bar sits above three panes: **Destinations** on the left, the call stage in the middle (it takes the width the window gives it; the video box scales with it), and the **Inspector** on the right, retabbed as **Quality** (the statistics, live through a call and kept after hangup), **Events**, **Devices** (microphone, camera, speaker, and the audio-processing toggles, which become active during a call) and **Diagnostics** (connection, identity, Do Not Disturb, SDK settings, connection test, export, SDK facts). Either side pane folds to a rail, and the arrangement persists. Dark is now the default theme (System and Light remain in the Appearance setting). Also fixed: the address field's History button did nothing in the desktop window; it now selects the Recents tab. Tests: the desktop spec covers the renamed tabs, folding a pane, the History button and the Devices tab; the phone spec checks the toolbar; the screenshot run adds the Devices and Diagnostics tabs.
- **SignalWire docs styling** — the UI now uses the design language of signalwire.com/docs, measured from the live site: Lexend for text, Instrument Sans for display type (headings, the dialed number, the dial pad digits) and JetBrains Mono for addresses, call ids, timers, statistics and the event log; the docs' near-white light theme with the SignalWire blue accent and its navy-black dark theme with the turquoise accent; flat cards with hairline borders and a soft shadow instead of translucent glass; blur only on the header; 8px controls and 12px cards; underline tabs; flat Call/End buttons (still green and red). Light and dark follow the system by default, and an **Appearance** setting (System / Light / Dark) in Diagnostics & Settings / the Session tab overrides it; the choice persists and is applied before the first paint. Under the hood every color, font and radius is a semantic token in `globals.css` (`bg-surface`, `text-muted`, `border-edge`, `bg-accent`, `font-display`, …) with the dark values under `[data-theme='dark']`, so components carry no raw palette utilities. The screenshot run adds light-theme passes for the phone and the workbench, and the suite covers the Appearance setting.
- **Desktop workbench, event log and address suggestions** — the UI was reviewed against what testers actually do (type or pick Fabric and SIP addresses, watch statistics, flip SDK settings between calls, on a desktop with devtools open) and reshaped around the phone rather than away from it:
  - From 1024px wide the phone column sits in the middle of a three-pane workbench: **Destinations** on the left (Directory, Recents, SWML, SIP and Subscribers as full-height tabs that fill the address field) and an **Inspector** on the right with **Call** (the statistics, live for the whole call and kept after hangup), **Events** and **Session** (connection, identity, Do Not Disturb, SDK settings, connection test, export, devices, SDK facts). The header's panel icons disappear there, clicking your name selects the Subscribers tab, and the in-call grid gains Hold and Share. Phone, tablet and landscape layouts are unchanged in structure; the phone-width column now applies below 1024px only.
  - An **event log** of what the SDK and the dialer did, in order — token minting and refresh, connection and registration changes, dialing and call status, call errors, SDK warnings, network issues appearing and clearing, ICE and recovery, device switches, hold/screen-share requests and refusals, DTMF, settings changes — kept in a bounded buffer on the service (`getEventLog$`, never through the store) with kind filters and a copy button, as an Events section of the Diagnostics panel and the Inspector's Events tab.
  - **Address suggestions** under the field while typing (Recents, then the Directory pages the SDK has loaded): Up/Down to choose, Enter to fill without dialing, Escape to dismiss.
  - Phone-layout fixes: the header icons carry labels on tablets and desktop; the active subscriber is a chip in the status bar (it opens the Subscriber panel) instead of 10px text under the clock; the resource, subscriber and device panels are taller; the Call Statistics panel hangs from the top without a backdrop so Mute, End and the meters stay usable while reading it (over the info column on landscape phones); Diagnostics lists the SDK settings first; the in-call keypad keeps the status line, number and timer in view; failed backend requests say what happened ("Backend unreachable", "rejected the API key", rate limit) with a Retry button, including on the startup error screen; an empty Devices panel offers to request microphone and camera access.
  - Tests: a `desktop` Playwright project (1280×800) for the workbench, specs for the event log and the suggestions, the screenshot run covers the workbench, and the fake directory and stats stubs are shared through `e2e/helpers.ts`.
- **Tester clarity** — the Call Statistics sheet lists the network issues behind a "Degraded" health reading and no longer flags every voice call as degraded; every tab of the resources panel has a search field (Directory search loads the whole directory as you type; SWML and SIP search is a `q` parameter on the listing endpoints that filters before paging); and the Diagnostics panel explains that the codec order applies to WebRTC and SIP calls, not to phone numbers, which use G.711. The connection test's media call no longer takes over the call screen (which unmounted the panel and lost the result, and left the screen up after the SDK hung up), and a call the SDK tears down itself (status `destroyed`) now returns the UI to the dialer.
- **Correctness and backend hardening** — pressing Enter after flipping the video toggle now places a video call (the Enter listener held a stale copy of the dial handler) and Enter in the Diagnostics field no longer dials; every `/api` route goes through one `gate()` helper (`X-API-Key` plus a per-IP rate limit), including the SWML/SIP listings, which had fanned out authenticated SignalWire REST calls for anyone who could reach the port; the unread `/api/calls` history/active/status/end routes, which listed every number a tester had dialed, are gone; token minting no longer fails when the subscriber listing is unavailable (503 for a requested subscriber id, the default subscriber otherwise); and the backend gained tests for the gate, subscriber resolution and paging.
- **Call a subscriber from the Subscribers panel** — the panel could only make the dialer *become* another subscriber; each row now also shows that subscriber's Fabric address (`/private/<name>`) with **Audio**/**Video** buttons that fill the dial field, the same pair the Directory, SWML, SIP and Recents rows use, and keeps **Switch** for the old behavior. Your own row is marked "(you)" and isn't dialable. `GET /api/subscribers` now returns each subscriber's addresses alongside id, display name and email, fetched per listed subscriber the way the SWML and SIP listings fetch theirs.
- **Tests and CI** — a Playwright suite (`frontend/e2e/`, `npm test`) that runs without SignalWire credentials through a dev-only `?e2e=1` seam, a screenshot run for every screen at four viewports (`npm run test:shots`), a pytest suite for the backend that shares a number-normalization fixture with the frontend, and a GitHub Actions workflow running lint, type-check, build and both suites.
- **Interaction and accessibility** — every sheet, modal and panel is a proper dialog (focus trap, Escape, focus return); keyboard shortcuts (Enter/Escape to answer/decline, `m` to mute, hold `0` for `+`); an installable PWA manifest with icons, safe-area padding for notched phones, and pinch-zoom re-enabled; console noise replaced by an app logger gated behind a setting.
- **Backend hardening** — one shared REST client, request timeouts, bounded page sizes, generic error bodies, redacted request logging, and removal of the unused `/api/auth/validate` and `/api/calls/incoming` stubs.
- **Tester tooling from the SDK** — a **Directory** tab listing the signed-in subscriber's SDK address book (`client.directory$`: other subscribers for browser-to-browser calls, video rooms, SIP endpoints, SWML scripts — the Subscribers/Rooms/Apps filters load the whole name-sorted directory so nothing hides behind "Load more"); a **Recents** tab (client-side call log with outcomes, durations and redial, replacing the single remembered number); a **Call Statistics** sheet behind the quality badge (RTT, jitter, loss, bandwidth estimate, negotiated codecs, ICE path, SDK recovery state and events, call id); live mic and remote **audio-level meters**; **Do Not Disturb** (`unregister()`); and **SDK Settings** in the Diagnostics panel — audio codec order, SDK log level, WebSocket tracing, relay-only (TURN) media and app debug logs — applied without a reload. The connection test gained its options (skip the media test, test length) and shows STUN/TURN reachability and device checks.
- **Call-flow fixes** — the Speaker toggle's "off" direction never worked (SDK `applySelectedAudioOutputDevice()` returns `false` with no device selected) and is now disabled where `setSinkId` is unsupported; the call timer starts when the far end answers (not when dialing starts) and the status line distinguishes "Ringing…"; DTMF is held until connected; a startup failure shows the error screen instead of spinning forever; a deleted saved subscriber no longer locks the app out; an incoming call during a dial is auto-rejected; pasted numbers like `(555) 123-4567` normalize the same way the backend does; a browser that blocks autoplay (e.g. after a reload that reattached a call) shows "Tap to enable audio"; media loss during a call shows "Reconnecting…" and defers to the SDK's recovery instead of hanging up on the first ICE failure.
- **Toolchain refresh** — Vite 8, Tailwind CSS 4, and typescript-eslint 8 on the frontend; the backend now depends only on what it uses (Flask, Flask-CORS, requests, python-dotenv), all on current releases.
- **Call-experience improvements** — verified on browser-to-browser, PSTN, and SIP test calls:
  - Instant mute and unmute. Audio resumes the moment you unmute.
  - Screen sharing follows the SDK's screen-sharing guide. It's offered only when SignalWire grants the call the `screenshare` capability (calls into a video room or conference), shows a disabled "Starting…"/"Stopping…" state while a share settles, gives a specific message for each failure, and can optionally include tab audio. Hanging up mid-share now removes the share from the room immediately.
  - Mute works from the moment a call starts dialing, so muting before the other side answers is honored.
  - Hanging up while a call is still being placed reliably cancels it.
  - If the server doesn't permit a hold, the app says so and the call continues.
  - Cleaner remote-audio playback and incoming-call handling.
- **Responsive layout & accessibility** — the UI now fits phones from 320px wide (the old forced 360×640 minimum is gone), phones in landscape (address field and dial pad side by side), tablets, and desktop. Header panels open as an overlay instead of squashing the dial pad, long SIP/Fabric addresses wrap, all icon-only buttons have accessible labels, and header/close buttons have 40px tap targets.
- **Call reattach across reloads** — the client is configured to resume an active call after a page reload (`reconnectAttachedCalls`), adopting reattached calls as they arrive. Verified on 2026-10-17 with `@signalwire/js@4.0.0-rc.5`: a page reloaded mid-call came back on the call screen, connected, with media flowing.
- **Subscriber picker** — a new toolbar icon in the dialer header opens a panel (`SubscriberPicker.tsx`) listing subscribers in the SignalWire space, so the app can authenticate as any of them instead of a hardcoded default. Backed by a new `GET /api/subscribers` endpoint (`backend/api/subscribers.py`) that trims each record down to id/display name/email and is gated the same way as the token endpoints, since subscriber records carry real PII. Switching reloads the page, since the SDK client's identity is fixed at construction.
- **SIP Credentials tab & per-channel dial options in the resource browser** — the SWML Scripts browser is now a tabbed `DialableResourcesPanel` (SWML Scripts + SIP Credentials, the latter backed by a new `GET /api/sip/credentials` endpoint mirroring the SWML one), and each address row shows explicit Audio/Video dial buttons instead of one generic button, since offering video requires the address's channel-specific `?channel=video` URL rather than just a dial-time flag.
- **Call quality badge & connection diagnostics** — a live signal-strength icon (plus a network-issue warning) appears in the call screen header, driven by the SDK's `call.qualityLevel$`/`qualityScore$`/`networkIssues$` observables (`CallQualityBadge.tsx`). A new Diagnostics panel, opened from a toolbar icon in the dialer header, runs `client.preflight()` against any number/address to test signaling/TURN/bandwidth before you dial, and can export the full SDK session diagnostics (`client.exportDiagnostics()`) as JSON (`DiagnosticsPanel.tsx`, `services/diagnostics.ts`).
- **In-call controls sheet** — a new "More" button on the call screen opens a bottom sheet (`CallControlsSheet.tsx`) for hold/resume (`call.toggleHold()`), screen sharing (shown when the browser supports `getDisplayMedia` and the call has the `screenshare` capability — see above), the device picker, and live toggles for echo cancellation / noise suppression / auto gain control (`call.self`), plus a diagnostics export shortcut.
- **Device picker** — a new panel (`DevicePicker.tsx`), reachable from both the idle dialer header and the in-call controls sheet, lists and selects microphone/camera/speaker using the SDK's `audioInputDevices$`/`videoInputDevices$`/`audioOutputDevices$` observables. Picking a speaker here is what makes the existing speaker toggle actually switch output, via `selectAudioOutputDevice`/`applySelectedAudioOutputDevice`.
- **Inline error banners instead of hard failures** — a new `callError` field on the call store surfaces failed calls/answers/holds, etc. as a dismissible banner (`ErrorBanner.tsx`) on the idle dialer or call screen, instead of taking over the whole app. SDK error types (`MediaAccessError`, `MediaTrackError`, `CallCreateError`, `PreflightError`, and a new `ClientNotReadyError` for actions attempted before `client.ready$` fires) are translated into human-readable messages by `describeCallError()` (`hooks/useSignalWire.ts`).
- **Session-health surfacing** — the client now tracks `client.ready$` continuously rather than only at initial mount, and escalates session-ending problems — token refresh failures and the `credential_no_refresh_handler` warning — to the UI via the same error banner, prompting a reload instead of silently failing in the background.
- **SWML Scripts browser** — a new panel (toggle button in the dialer header) lists the SignalWire space's SWML scripts and their dialable addresses, and lets you tap one to fill the dial field. Backed by a new `GET /api/swml/scripts` endpoint (`backend/api/swml.py`).
- **Video calls** — a camera toggle in the address field places video calls (upstream is audio-only). The call screen shows remote video full-screen with a local picture-in-picture preview, and the camera can be turned on mid-call, even on a call that started audio-only.
- **Direct SIP/Fabric-address dialing** — the dial field now also accepts SIP URIs (`sip:user@domain`) and Fabric addresses (`/public/room-name`) alongside phone numbers; both skip E.164 formatting.
- **SignalWire JS SDK** on the published release candidate `@signalwire/js@^4.0.0-rc.5` (upstream was on `4.0.0-rc.0` when this fork branched).
- **Dev environment** — added a `.devcontainer/` (Python 3.12 + Node 20) that bootstraps the venv and runs `npm install` automatically, with ports 5001/5173 pre-forwarded.
- **Documentation** — expanded `CLAUDE.md` with architecture notes for the above, and credited the upstream project in the README.
