# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A reference web dialer for SignalWire's Fabric/WebRTC stack and a hands-on testing tool for the SignalWire Browser SDK, not a production app. Weigh hardening against convenience accordingly. Two services:

- `backend/` is a Flask app on port **5001**. It mints SignalWire subscriber tokens and lists the space's resources. It does **not** route media or signaling.
- `frontend/` is Vite + React + TypeScript on port **5173**. All WebRTC (signaling, media, DTMF) goes through the published npm package `@signalwire/js` (`^4.0.0-rc.5` in `frontend/package.json`, `4.0.0-rc.5` in the lockfile; npm's `latest`/`rc` tag; there is no stable `4.0.0`). To read SDK internals, read `node_modules/@signalwire/js/dist/index.mjs` or clone `signalwire-js` at the matching tag (its `examples/` are the authoritative v4 API guide). Never edit the SDK from here.

`README.md` is written for SignalWire customers. This file holds what you need to work on the code.

## Rules

One line each; the section named in parentheses holds the reasoning. Read it before relaxing a rule.

- The frontend never stores or caches tokens; the SDK calls the `credentialProvider` callbacks on demand. (Token lifecycle)
- Never call `signalWireService.disconnect()` from a hook cleanup. Only `App.tsx`'s `beforeunload` does, and not while `hasActiveCall()`. (Singleton lifetime; Reattach)
- Don't change `beforeunload`, the `calls$` adoption, or the `persistSession` omission in isolation. (Reattach)
- `endCall()` calls `handleCallEnded()` before `await call.hangup()`. Don't reorder. (Call-ended detection)
- A `status$` `disconnected`/`failed` that the peer connection itself reports is media loss, not call end; the grace timer ends such a call and hangs up. (Call-ended detection)
- Don't simplify `refusalOf()` back to a bare `await call.transfer()`/`toggleHold()`. (Transfer and hold)
- Transfer is hidden behind `SHOW_TRANSFER` (`false`) in `CallScreen.tsx`; keep `TransferModal.tsx`, `transferCall` and the skipped spec so flipping it restores the feature, and keep the README silent on transfer. (Transfer and hold)
- High-frequency observables never go through `useCallStore`. (High-frequency observables)
- Don't drop the `no_inbound_video` filter in `relevantIssues()` without re-testing an audio-only call. (Call quality vs. health)
- Don't remove the remote-audio fallback without verifying audio on an inbound and an outbound call. (Remote audio)
- The speaker bar reads `services/remoteAudioMeter.ts`, fed from `handleRemoteMedia()`, never `call.remoteAudioLevel$`. (Remote audio)
- Don't enable `savePreferences` or `persistSession` on the SDK client. (Settings; Reattach)
- Mute is local. Don't switch it to the SDK's `self.mute()`. (Mute)
- A call that has reached `connected` stays connected in the UI and for DTMF (`connectedCall`); don't gate on `call.status` again without re-testing a call with early media. (In-call timer)
- `toggleScreenShare` runs directly from the click with no `await` before `startScreenShare()`; `endCall()` stops a share before hanging up. (Screen share)
- No window-level keyboard shortcuts. Keys act only where focus is: Enter in the address field dials, the suggestion list's keys, a focused keypad key, and `useDialog`'s Escape and Tab. (Keys, cards and the call toolbar)
- Every `/api` route goes through `gate()`. Token minting must never be open. (Backend gate)
- No bare `console.*`; use `utils/log.ts`. (Conventions)
- Keep number normalization and dial-address detection in sync between `signalwire.ts`/`address.ts` and `utils/signalwire.py`, and update the shared fixture. (Conventions)
- The field is the dial string: `useDialFieldStore` keeps `wantsVideo` and a Fabric address's `?channel=` in step (`withChannel`/`channelOf` in `address.ts`); `makeCall` only normalizes, passes `receiveVideo` explicitly and adds `from` for a phone number. (Per-channel dialing)
- Joining with the camera off is hidden behind `SHOW_CAMERA_OFF_JOIN` (`false`) in `useDialFieldStore.ts`; keep `cameraOff`, the service's `cameraOff` parameters and the skipped specs so flipping it restores the feature, and keep the README silent on it. (Per-channel dialing)
- The caller ID (`useCallerIdStore`, localStorage `dialer_caller_id`) reaches `dial()` as `from` for phone numbers only: `Dialer.tsx` gates it and `signalwire.ts:makeCall` drops it for SIP/Fabric destinations. The list is the space's numbers plus verified caller IDs (`GET /api/caller-ids`), never free text. (Caller ID)
- Never use the bare word `container` anywhere in `frontend/src`, comments included. (Styling)
- Colors, fonts and radii come from the semantic tokens in `globals.css` (`bg-surface`, `text-muted`, `border-edge`, `bg-accent`, `font-display`, `font-mono`, …); no raw palette utilities (`bg-white/x`, `text-gray-x`, `emerald-*`, …) in components. (Styling)
- The Appearance setting is applied by `services/theme.ts`'s `applyTheme()`, never through `applySettings()`. (Styling)
- Preserve each file's line endings; the original files are CRLF. (Conventions)
- After editing `signalwire.ts` or `useCallStore.ts`, restart the dev server before trusting a failing Playwright run. (Testing)
- Change frontend dependencies with `npx npm@11 install ...`, not npm 10. (Environment)
- Changes to call-end, mute, reattach, screen share, hold/transfer or remote audio need a real-call test; the e2e suite drives stubs. (Testing)
- README edits stay customer-facing. (Conventions)
- Workbench panes are `role="region"`, never `useDialog`; keep `WORKBENCH_QUERY` and the `#root` cap in `globals.css` on the same 1024px bound. (Workbench)
- Inspector tabs are Quality · Events · Devices · Diagnostics, and tab names stay unique on the page: the workbench and screenshot specs select tabs by name without scoping. (Workbench)
- `AppBar` is the only `glass-bar pt-safe` element on the phone layout; the a11y spec counts it. (Top bar)
- Keys are `keypad-grid` + `key-button`; the digit keeps `dial-button-number` (the dialer spec reads it). No round `dial-button`. (Styling)
- The theme default is `dark`; a spec that needs `system` seeds `dialer_settings` first. (Styling)
- The event log is `logEvent()` → `getEventLog$()` only: never through `useCallStore`, never through `log.*`. (Event log)
- Failed backend requests get their copy from `describeFetchError` in `services/api.ts`, not `err.message`. (Conventions)

## Environment

`backend/.env` is the only env file. It holds `SPACE_NAME` (the space's full hostname), `PROJECT_ID`, `AUTH_TOKEN` (a Dashboard API token; the Fabric endpoints accept the Voice, Messaging, Fax or Video scope, and the caller ID listing also needs Numbers for the phone numbers and Voice for the verified caller IDs), `PORT`, `FRONTEND_URL`, `DIALER_API_KEY` and `FLASK_DEBUG` (leave it off: the Werkzeug debugger allows code execution and the server binds `0.0.0.0`). `vite.config.ts` loads the same file: `FRONTEND_URL`'s hostname goes into `allowedHosts` (tunneled dev) and `DIALER_API_KEY` is baked into the bundle as `import.meta.env.VITE_DIALER_API_KEY`. Restart `npm run dev` after changing the key. The key ships in the public bundle, so it is a bot deterrent paired with the rate limit, not a secret.

Vite 8 requires Node 20.19+. npm 10.8.x crashes with `Cannot read properties of null (reading 'edgesOut')` when *changing* frontend dependencies (an arborist peer-set bug triggered by `@vitejs/plugin-react`'s optional peers), so run those installs with `npx npm@11 install ...`. A plain `npm install`/`npm ci` from the lockfile works on 10.8.

`.devcontainer/` (Python 3.12 + Node 20, forwards :5001/:5173) runs `post-create.sh`, which creates the venv and runs `npm install`; `backend/.env` must still be created by hand. Quirks:
- The Flask dev server runs with the reloader on; multi-file backend rewrites can crash it mid-edit. Restart it.
- `pkill -f 'vite'` matches and kills the shell running it; use `pkill -f 'vit[e] --host'`.
- `@playwright/test` is locked at 1.64.1. Run `npx playwright install --with-deps chromium` once, as CI does.
- There is no `file` command. Check line endings with `grep -c $'\r' <file>` (0 means LF).
- Scripted edits of CRLF files must open them with `newline=''` (Python) or the equivalent; a text-mode read/write silently converts the whole file to LF.

## Testing

`cd frontend && npm test` runs the Playwright suite in `frontend/e2e/` (the `phone` project at a phone viewport and the `desktop` project at 1280×800; `playwright.config.ts` starts or reuses the dev server). It needs **no SignalWire credentials**: pages open with `?e2e=1`, a dev-only seam in `useSignalWire.ts` (`E2E_SEAM`, gated on `import.meta.env.DEV`) that registers the hook's callbacks on the service without calling `initialize()`. Tests then stub service methods via `page.evaluate(import('/src/services/signalwire.ts'))` (private members are reachable at runtime), fire callbacks like `s.onIncomingCall(...)`, and drive screens with `useCallStore.getState().setCallState`; see `e2e/helpers.ts`, which also holds the fake SDK directory (`FAKE_DIRECTORY`) and the stats stubs (`STATS_STUBS`) shared by both projects. A spec that needs an SDK error class imports it from the pre-bundled module URL the page already loaded (`performance.getEntriesByType('resource')`, `/.vite/deps/@signalwire_js.js`), so `instanceof` holds. `npm run test:shots` (the `shots` project) takes non-asserting screenshots of every screen at six viewports plus light-theme passes into `e2e/screenshots/` (gitignored).

Two traps:
- Vite HMR timestamps modules you've just edited, so the dev server's and the test's module instances can diverge. A run where every stub silently has no effect (an empty `__log`, the fake directory never appearing) means exactly that: restart the dev server before reading anything into the failures.
- The dev server runs React in StrictMode, which mounts effects twice: a component that fetches on mount fires two requests and keeps the second, so a `page.route` stub meant to fail "once" is consumed by the discarded first fetch. Stub by a flag the test flips instead.

Backend: `python -m pytest backend/tests`. `test_numbers.py` and `e2e/dialer.spec.ts` share `frontend/e2e/fixtures/dial-normalization.json`, so a change to number normalization on one side fails the other side's test until it's mirrored. The listing and auth tests drive the Flask test client with fakes bound into each blueprint's namespace (`monkeypatch.setattr(api.auth, 'get_client', ...)`), resetting `utils.security._buckets` and the listing caches per test.

CI (`.github/workflows/ci.yml`): `npm ci`, lint, `tsc --noEmit`, build, Playwright (Chromium, traces uploaded on failure), then `py_compile` and pytest.

The e2e suite drives stubs. Anything touching call-end detection, mute, reattach, screen share, hold/transfer or remote audio needs a real call (browser-to-browser via two subscribers, a SWML script, or PSTN). Driving `signalWireService` directly from a script leaves `useCallStore` on the dialer, so such a script must set `isInCall`/`callStatus` itself before the call screen exists.

## Architecture notes that aren't obvious from the file tree

### Token lifecycle
Backend `/api/auth/token` and `/api/auth/refresh` both call `SignalWireClient.create_subscriber_token`; refresh just mints a fresh one (1-hour TTL). The frontend never stores tokens: `signalwire.ts` passes a `credentialProvider` with `authenticate`/`refresh` callbacks to `new SignalWire(...)`, and the SDK calls them on demand (~80% of TTL). The backend mints a **plain SAT** (no `sat:refresh` scope, no DPoP fingerprint), so the SDK relies on our `refresh()` callback rather than the Client Bound SAT path. `signalwire.ts` subscribes to `client.warnings$`: `credential_refresh_fallback`/`credential_no_refresh_handler` mean refresh isn't wired correctly, and `credential_no_refresh_handler` and refresh failures are escalated to the error banner with a reload prompt.

The default identity is the reference `swdialer` (`auth.py`'s `_TOKEN_REFERENCE`); SignalWire creates or reuses a subscriber per reference. A client-chosen subscriber is accepted **only by id**, validated against `api/subscribers.py`'s `get_subscribers_cached()` and mapped back to that subscriber's email as the reference (`_resolve_reference`), never a raw client-supplied reference, which would be an IDOR. If the listing fails, a *requested* id answers 503 "Subscriber lookup unavailable" (transient; the frontend forgets a saved subscriber only on a 400 "Unknown subscriber"), while the default reference is minted anyway.

### Backend gate and rate limits
`utils/security.gate(request, scope, limit)` checks `X-API-Key` against `DIALER_API_KEY` (fail-closed: 503 when unset, 401 when wrong) and applies a per-IP sliding-window rate limit keyed by `scope`, so one endpoint's traffic doesn't starve another's: `token` (10/min, real tokens), `subscribers` (10/min, PII), `swml`/`sip`/`calls` (30/min, "load more" pages), `caller_ids` (30/min, up to two REST calls per uncached request). Each listed item costs an authenticated REST call with the account's credentials, so an ungated listing is a free amplifier against the account's API quota. The axios instance (`services/api.ts`) sends `X-API-Key` on every request. `utils/security.bounded_page()` clamps `offset ≥ 0`, `1 ≤ limit ≤ 50`. Every `requests` call has a 10 s timeout, and error bodies are generic (details go to the server log, never `str(e)` to the client).

### Backend listings (subscribers, SWML scripts, SIP credentials)
`GET /api/subscribers`, `GET /api/swml/scripts` and `GET /api/sip/credentials` list resources with their dialable addresses, paginated for a "load more" UI. The SWML and SIP blueprints are structurally identical and deliberately duplicated: listing metadata is one cheap paginated call, but each resource's *addresses* is a separate REST call, so metadata is cached in-process for 60 s while only the requested page's addresses are fetched fresh via a small `ThreadPoolExecutor`. `q` (trimmed and capped by `utils/security.query_param`) filters the cached metadata before slicing, so `total`/`has_more` describe the matches and `offset` is relative to the filtered list; the frontend's `items.length` load-more offset depends on that. `/api/subscribers` returns each subscriber's `addresses` the same way, which is what lets `SubscriberPicker.tsx` offer Audio/Video call buttons beside "Switch". `SignalWireClient` (`utils/signalwire.py`) walks paginated endpoints through `_get_all_pages`; `get_client()` returns `None` when the env isn't configured (each endpoint then answers 500).

### Directory tab
The resources panel's first tab is the signed-in subscriber's own address book from the SDK (`client.directory$` → `DirectoryAddressList.tsx`): other subscribers (`/private/<name>`), video rooms, SIP endpoints (`call`), SWML scripts (`app`), with a type badge and filter, and your own address marked "(you)" and not dialable (`getOwnAddressIds()` from `client.user.addresses`, plus a `resourceId` match against the token's subscriber id). The SDK pages it **100 at a time, sorted by name, with no type filter**, so on a space with many SWML scripts the subscribers and rooms sit pages deep. The type filters and the text search therefore auto-`loadMore()` until `hasMore$` is false (`isNarrowing` = a chip or a non-empty query), while "All" pages manually. It deliberately doesn't use `ResourceAddressList`'s offset/limit `fetchPage`: the SDK owns the list (page 1 loads when `hasMore$` is subscribed, `loadMore()` appends, the `Directory` lives for the client's lifetime), so the component subscribes directly and renders through the shared `AddressRowList`. The panel's `activeTab` is controlled by `Dialer.tsx` so other UI can open a specific tab.

### Recents
A client-side call log (`useRecentsStore.ts`, Zustand `persist` → localStorage `dialer_recents`, newest first, capped at 50): destination (the field text, `?channel=` included), label, direction, outcome (`answered`/`missed`/`declined`/`failed`/`cancelled`), timestamps, video flag and the signed-in subscriber. Empty field + Call fills in the last outbound destination with its video choice; Call again dials it. Recording happens in `useSignalWire.ts`, where direction and outcome are known: `makeCall` (start; `setCallId` once `dial()` resolves; `failed` on throw), `onIncomingCall`, `onIncomingCallAutoRejected` (`missed`, deduped per call id), `onCallConnected` (`markConnected`, idempotent), the hook's `endCall` (`cancelled` if never connected, recorded *before* the service call, whose `handleCallEnded` fires `onCallEnded` synchronously), `rejectCall` (`declined`), and `onCallEnded` (whatever is still in progress). Entries left `in-progress` by a reload are settled on rehydrate. `onSelectAddress(path, video, label?)` carries the picked row's display name so the log reads "Alice", not a URL.

### Per-channel dialing
Each address carries a `channels` map (`{audio, video, messaging}` → full dial URL with the right `?channel=`). The SDK's `buildOptionsFromDestination` (rc.5) reads `?channel=` off the destination string (`video` → `{audio, video, receiveVideo: true}`, `audio` → `{audio, video: false}`) and merges it *under* the app's options, so the app's `video` wins but `receiveVideo` would otherwise stay at its preference default of `false` (a `sendonly` video offer). Hence the **field is the dial string**: `useDialFieldStore` keeps `wantsVideo` and the text in step through `withChannel()`/`channelOf()` in `utils/address.ts`. For a Fabric address the toggle *is* the `?channel=` param: toggling rewrites it (on → `channel=video`, off → `channel=audio`, a bare address stays bare = audio), and editing the text re-derives the toggle, case-insensitively, keystroke by keystroke; there is no latched state the text doesn't show. A phone number forces it off (button disabled with a hint); a SIP URI or an empty field keeps the user's choice and never gets a param. `selectAddress(path, video, label)` rewrites the path to the flag, so every list pick lands with its channel visible. `makeCall` then only normalizes and calls `client.dial(to, { audio: true, video, receiveVideo: video })`. `DialableResourcesPanel.tsx` is the tabbed picker (Directory / Recents / SWML / SIP); the SWML and SIP tabs delegate to the resource-agnostic `ResourceAddressList.tsx`, and `DialButtons` renders the Audio/Video pair everywhere. Video is disabled unless a distinct `video` channel URL exists. Selecting fills the field; it does not auto-dial.

**Joining with the camera off is built but hidden.** `useDialFieldStore.cameraOff` is a send-side choice: a camera button that takes **From**'s slot in the dial row while Video is on. `makeCall`/`answerCall` then pass `video: false, receiveVideo: true`, and the in-call Camera button takes `toggleCamera`'s never-sent-video branch, `self.addVideoInputDevice()`. That branch is only for a call with no local video track *and* no server-side video mute: Camera off is `muteVideo()`, which drops the track and mutes the member's video, so Camera on must be `unmuteVideo()`, which re-acquires the camera and sends `call.unmute` (`addVideoInputDevice()` there would leave the room showing the member as video-muted). It is off by default: the button renders only when `SHOW_CAMERA_OFF_JOIN` (`false`) is on, and `Dialer.tsx` and `useSignalWire.answerCall` ignore `cameraOff` while it is off. To restore: flip the flag, un-skip the four camera-off tests in `dialer.spec.ts` and drop its hidden-toggle test, and add the README rows. Don't substitute dialing with video and muting.

### Caller ID is a dial option, not a setting
SignalWire accepts as the caller ID of a call to a phone number only a number the project owns or an external number it has verified, so the picker (`CallerIdSheet.tsx`, opened from the **From** button beside Video, locked out for SIP/Fabric addresses) lists exactly those and has no free-text entry. `GET /api/caller-ids` (`api/caller_ids.py`) merges `GET /api/relay/rest/phone_numbers` (scope **Numbers**) and `GET /api/relay/rest/verified_caller_ids` (**Voice**; `verified: true` only) through `SignalWireClient.relay_api_base` (the Fabric `api_base` doesn't serve them), trimmed to `{id, number, name, kind}`, unpaged, and caches only a complete result for 60 s so a source that failed (named in `failed`) is retried. The choice lives in `useCallerIdStore` (persisted), not in `DialerSettings` (those are pushed into the SDK by `applySettings()`) and not in `useDialFieldStore` (unpersisted, cleared on call end). `Dialer.tsx` passes it as `from` only for a phone number and stores it as `outboundCallerId` for the call card's "From" line; `signalwire.ts:makeCall` drops it for SIP/Fabric destinations and omits the key when unset. The SDK's public `DialOptions` doesn't declare `from`; `CallOptions` does, and `dial()` spreads its options into the call session whose `from` becomes the invite's `caller_id_number`, hence `OutboundDialOptions = DialOptions & Pick<CallOptions, 'from' | 'fromName'>`.

The platform presents the chosen number on the PSTN leg. A number the project neither owns nor has verified is refused at call creation rather than replaced: `dial()` rejects with `CallCreateError`, whose JSON-RPC message carries a 422 `not_purchased_or_verified` on `caller_id_number`, and `describeCallError` maps it to its own message (the picker lists only valid numbers, so this is a saved choice whose number has since been released). With no `from`, the server picks the number. The Fabric subscriber resource has a `send_as` field the app neither reads nor sets.

### Call state is split across three places, deliberately
- `SignalWireService` (`services/signalwire.ts`) owns the SDK `Call` objects. It distinguishes `pendingCall` (ringing, not yet answered) from `currentCall` (active). Incoming calls that arrive while `currentCall` is set are auto-rejected.
- `useCallStore` (Zustand) holds UI state: `isInCall`, `isIncoming`, `callStatus`, mute/speaker flags.
- `useSignalWire` is the bridge: it wires SDK callbacks (`onIncomingCall`, `onCallEnded`, `onCallConnected`) into store updates.

### High-frequency observables bypass the store
`useCallStore` is for low-frequency, multi-consumer state. Anything that ticks fast with one transient consumer (`networkMetrics$` at 1 Hz, `getStats()` polling, `localAudioLevel$` and the remote meter's `level$` at ~30 fps) is read by the consuming component straight from a service passthrough getter (`getNetworkMetrics$()`, `getLocalAudioLevel$()`, …) and never routed through `setCallState`, which would re-run every selector subscriber on each tick. `CallStatsSheet.tsx` and `AudioLevelMeter.tsx` (writes `scaleX()` to the DOM directly) follow this. Sheets share `SheetPrimitives.tsx`. Subscribing to `localAudioLevel$` "engages the local audio pipeline", after which the sender carries a processed track; `applyMicMute()` disables both the `localStream` track and the sender track, so mute should still hold; confirm it on a real call when changing this.

### Call quality vs. health
The stats sheet's **Quality** row is the SDK's MOS (`qualityLevel$`/`qualityScore$`, an E-model score from RTT, jitter and cumulative loss). **Health** is the SDK's issue detector (`networkIssues$`; `isNetworkHealthy$` is "the list is empty"): `no_inbound_audio`, `no_inbound_video`, `high_rtt`, `high_jitter`, `high_packet_loss`. They legitimately disagree, so the sheet lists the active issues under Health. `relevantIssues()` in `signalwire.ts` drops `no_inbound_video` while `remoteHasVideo` (set in `handleRemoteMedia`, cleared per call) is false; the store's `networkIssueCount` and the sheet's passthroughs both go through it. Don't widen the filter.

### The SignalWire singleton must outlive React unmounts
`useSignalWire`'s cleanup deliberately does **not** call `signalWireService.disconnect()`; only `App.tsx`'s `beforeunload` listener does. StrictMode or re-renders would otherwise tear down the registration mid-call. To "reset" the SDK, reload the page; don't re-initialize.

### Call reattach is enabled, and that constrains `beforeunload`
`new SignalWire(...)` passes `reconnectAttachedCalls: true`, so the SDK records each active call in `sessionStorage` and replays it as `verto.invite` with `reattaching: true` on the next `init()`, which carries a live call across a reload. A WebSocket reconnect doesn't reattach: the client resumes its session (`signalwire.connect` with the previous protocol) and the call carries on. Three things hang together: (1) `beforeunload` skips `disconnect()` while `hasActiveCall()`, because `client.disconnect()` clears the attach records too; the cost is that closing a tab mid-call doesn't hang up, and the far end waits for the media timeout. (2) Reattached calls are pushed straight into `session.calls$`, bypassing `dial()` and `incomingCalls$`, so `signalwire.ts` subscribes to `calls$` and adopts any untracked non-terminal call into `currentCall` (`adoptUntrackedCall()`), guarded by `isDialing` (`dial()` also lands in `calls$` before it resolves) and by `preflightInProgress` (`client.preflight()`'s media test dials through the client too; without the guard the test call would take over the call screen and unmount the Diagnostics result). (3) `persistSession` is deliberately off (see the comment at `new SignalWire(...)`); it would also break `switchSubscriber()`. A failed reattach drops the records and leaves the UI on the dialer. Chromium exempts pages with an active microphone capture from autoplay blocking, so "Tap to enable audio" rarely shows there; Safari differs.

### Remote audio has a fallback path
Besides `remoteStream$`, `setupRemoteAudioFallback` polls `call.rtcPeerConnection` and attaches a `track` listener directly. Both paths feed `handleRemoteMedia`: a stream with video goes to the remote `<video>` element (which then also plays the audio, so the audio sink is cleared), and audio-only goes to `playRemoteStream`, which renders into a single `<audio id="sw-remote-audio">` on `document.body` (skipping tracks it's already playing; both paths deliver the same track in different `MediaStream` wrappers).

The speaker bar doesn't use the SDK's `remoteAudioLevel$`, which is fed only by `remoteStream$` and so misses the fallback path. `services/remoteAudioMeter.ts` meters the stream `handleRemoteMedia` routes to the sink instead: a `MediaStreamAudioSourceNode` → `AnalyserNode` tap on the tone service's shared `AudioContext` (`toneService.getAudioContext()`, resumed by the same gesture that unblocks remote audio), nothing connected to the destination, the SDK's analyser settings and RMS so the two bars read alike, deduped by audio track id, streams without audio tracks ignored, detached in `handleCallEnded()`. `getRemoteAudioLevel$()` returns its `level$`. The `stats` spec drives it with an oscillator through `handleRemoteMedia`.

### Call-ended detection is redundant, and media loss is not call end
No single SDK signal covers every way a call ends, so the service ends a call on any of: (1) a terminal `status$` that isn't media loss: `destroyed` (the SDK's own `hangup()` emits `disconnecting` then `destroyed`), or `disconnected`/`failed` while the peer connection reports something else (the far end's bye arrives as `disconnected` with the connection still up), (2) the peer connection reporting `closed` (rarely fires: `close()` dispatches no event), (3) a `recoveryEvent$` `max_attempts_reached`, or (4) a grace timer after ICE `disconnected`/`failed` expires with media still down, which also hangs up (`hangUpAbandonedCall()`): a call ended only locally leaves the far end on a silent call until the server times the media out. `status$` also carries the peer connection's own `connectionState`, so a `disconnected`/`failed` that the connection itself reports goes to (4), not (1); a brief network drop then recovers by itself (ICE back to `connected`) instead of ending the call. ICE `failed` alone does not end the call: the SDK's `CallRecoveryManager` may be recovering it, so `monitorPeerConnection` marks `isMediaDisrupted` ("Reconnecting…") and arms the timer. The recovery manager is driven by the stats monitor, browser `offline` events and WebSocket re-auth, **not by ICE state**, so `recoveryState$` can be `idle` while the peer connection is down; hence the timer, sized from the recovery preferences and extended once if the SDK is mid-`recovering`. Every peer-connection handler checks it still belongs to `currentCall` and is removed in `cleanupCallSubscriptions()`: the old connection's `closed` fires after `hangup()` and must not tear down a newer call. Every read of `call.rtcPeerConnection` goes through `peerConnectionOf()`: the getter throws once the call is destroyed, and `status$` delivers asynchronously, so the far end's `disconnected` arrives after that. `e2e/recovery.spec.ts` covers the state machine with stubs; a change here needs a real-call test (drop Wi-Fi mid-call).

### Mute is local, not the SDK's `self.mute()`
Mute stays on the client so it is instant on every call type. `toggleMute()` records the intent in `isMicMuted` (even before the `Call` exists; Mute is live on "Calling…") and `applyMicMute()` disables both `call.localStream`'s mic track and the sender track (on answer, `localStream$` emits before the track is attached to the sender). `localStream$` re-applies it when the SDK swaps the mic track. `isMicMuted` is reset at the start of `makeCall()`/`answerCall()`/reattach adoption, not in `setupCallSubscriptions()`, which runs after the user may already have tapped Mute.

### The in-call timer runs from `connectedAt`, and remote audio may need a tap
`connectedAt` is set once per call in `onCallConnected` (`status$` re-emits `connected` after an ICE restart, which must not restart the timer). The pre-answer status line follows `call.status$` (`trying`/`connecting` → "Calling…", `ringing` → "Ringing…"). A connected call stays connected: after early media, `status$` goes `ringing` → `connected` (media path up) → `connecting` (the far end answers) and stays on `connecting`, so `connectedCall` records the call that has reached `connected`, the `status$` handler ignores its later `trying`/`connecting`/`ringing` (the event log still shows them), and DTMF is gated on `connectedCall`, not `call.status`. DTMF is dropped until then. If `play()` on the remote sink is refused by the autoplay policy (e.g. a call reattached after a reload), `onRemoteAudioBlocked` sets `needsAudioUnlock` and `CallScreen` shows "Tap to enable audio", which calls `resumeRemoteAudio()`. `toneService.primeOnFirstGesture()` (App.tsx) resumes the shared `AudioContext` on the first gesture so a fresh tab doesn't ring silently; `DialPad` key tones use the same context.

### Tester settings live in `services/settings.ts`, applied without a reload
`DiagnosticsPanel.tsx` edits `DialerSettings` (audio codec order, default PCMU, PCMA, Opus; SDK `logLevel`; `debug.logWsTraffic`; `relayOnly`; this app's `debugLogs`; and the Appearance `theme`, which `applyTheme()` applies, not `applySettings()`), persisted in localStorage `dialer_settings`. `signalwire.ts` reads them at `new SignalWire(...)` and `applySettings()` applies changes live: `setLogLevel`/`setDebugOptions` are SDK globals (immediate); `preferredAudioCodecs` and `relayOnly` are read at each offer/answer and peer-connection creation, so they apply to the *next call*. Don't enable `savePreferences`: it would persist device prefs into SDK storage and interact with `switchSubscriber()`. The panel also runs `preflight()` (`skipMediaTest`, `duration`) and shows the full result. The media test is a real audio call the SDK places through `client.dial()` and hangs up itself, so `runPreflight()` sets `preflightInProgress` for the `calls$` adoption to ignore it.

### Do Not Disturb is `unregister()`, and the SDK can switch devices on its own
`setDoNotDisturb(true)` calls `client.unregister()` (stay connected, stop receiving calls); `isRegistered$` drives the store's `isRegistered`, the switch in `SubscriberPicker.tsx`, and a `BellOff` beside the status dot, which stays green because `ready$` ignores registration. Session-only: every load registers again. A caller dialing a subscriber in DND gets `422 no_devices_or_registrations` wrapped in `CallCreateError`, which `describeCallError` maps to "isn't online … or in Do Not Disturb". The inbound caller id of a browser-to-browser call arrives as `subscriber://<name>`, which `formatPhoneNumber` strips. `client.deviceRecovered$` (device unplugged or default changed) surfaces through `onClientNotice` → store `clientNotice` → an info `ErrorBanner`.

### Screen share is gated on the `screenshare` capability
The control shows only when the browser has `getDisplayMedia` *and* `call.self.capabilities.screenshare$` is true. The server grants it on calls into a video room and not on 1:1 calls, where a share leg is refused because it attaches to a room *participant*. `call.self$` is typed as `CallSelfParticipant`, which doesn't declare `capabilities`, so the code narrows with `instanceof SelfParticipant`; `distinctUntilChanged()` is needed because `self` is replaced on every `call.joined`. `describeScreenShareError()` in `useSignalWire.ts` maps the SDK guide's error table; the sheet disables the row during `starting`/`stopping`. `toggleScreenShare(withAudio)` must run directly from the click (an `await` before `startScreenShare()` loses the user gesture for `getDisplayMedia`). `endCall()` stops an active share before `call.hangup()`, so the share leg ends with the call.

### Transfer and hold report their outcome on `call.errors$`
`call.transfer()` and `call.toggleHold()` are `verto.modify` requests; the server's answer arrives in the result envelope (`result.result.error`) and surfaces on `call.errors$` (non-fatal), so the request resolves either way. `refusalOf()` in `signalwire.ts` wraps both: `errors$` is a `ReplaySubject(1)` on the asap scheduler, so it lets the replay of the call's previous error pass before arming, runs the request, flushes once more, and returns any refusal for the caller to rethrow. Hold is purely server-side (no SDP or direction change), so the UI's `isOnHold` is optimistic and reverted on a detected refusal.

The transfer control is hidden: `SHOW_TRANSFER` (`false`) in `CallScreen.tsx` gates the toolbar button, the More-sheet row and `TransferModal`. `CallToolbar` and `CallControlsSheet` take `onOpenTransfer` optionally and render nothing without it. Flipping the flag, un-skipping `dialer.spec`'s Transfer-field test and reverting the three `toHaveCount(0)` Transfer assertions (two in `dialer.spec`, one in `workbench.spec`) restores the feature.

### The top bar is shared and its status pill is live
`AppBar.tsx` is the top bar of every layout: the workbench renders it once above the panes, and on phones `Dialer.tsx`, `CallScreen.tsx` and `IncomingCall.tsx` each render it themselves (`!workbench`), so exactly one exists at a time. It carries the wordmark, the connection pill (`role=status`: green, or pulsing amber "Reconnecting…" when `ready$` drops; a BellOff while `isRegistered` is false), the active subscriber as a chip (selects the Subscribers tab in the workbench, opens the Subscriber panel on phones), the phone layout's panel buttons as children, and a sun/moon toggle (`desk` widths) that writes the Appearance setting through `saveSettings` + `applyTheme` and follows `<html data-theme>` with a MutationObserver. The quality badge lives in the call card's status strip, next to the timer and the call id (copy button "Copy Call ID", the same name and value as the stats sheet's, which `stats.spec` relies on). From 640px to 1023px (not `short` landscape phones) `globals.css` caps `#root` to a 40rem column.

### Keys, cards and the call toolbar
`DialPad.tsx` is the 12-key pad in two modes: `dial` (hold 0 for `+`, a Delete row that clears everything when held 2 s) and `dtmf` (digits only). `Dialer.tsx` renders the Video toggle and the Call button in a row under the address card; the keypad is always shown on phones and folded behind "Show keypad" in the workbench (localStorage `dialer_keypad`). `CallScreen.tsx` is one card: status strip, the always-mounted `<video>` pair (hidden unless `showVideoUI`, replaced by the DTMF pad while the keypad is open), the level meters, then `CallToolbar.tsx` with every control. The status line is the first `aria-live="polite"` element on the phone call screen (`helpers.callStatusText` reads it). `IncomingCall.tsx` is a card with Decline/Accept. There are no keyboard shortcuts anywhere: a key acts only on what has focus, so it never does something other than what the focused control shows (a page-wide Enter on top of a focused button's own activation would act twice).

Layout rules that keep every size usable (check with `npm run test:shots`): the address type label is its own fixed-height line under the address card so the first keystroke doesn't move the field, and the From/Video/Call row is right-aligned with only the caller ID name allowed to truncate. In the call card only the *stage* (video box or DTMF pad) scrolls; the status strip, meters and toolbar are pinned so End can't leave the screen, and on `short` (landscape) screens the status strip sits beside the stage. `CallToolbar` is a 4-column grid (8 on `short`; 5/9 with Transfer), so End is always last; buttons stack icon over label except on `wide` screens (≥1224px). On `low` screens (501–800px tall) an open keypad trims the toolbar to Mute, Keypad, Speaker and End and hides the meters, and the DTMF pad shrinks in tiers. The Destinations tab strip is set tight (12px, `px-1.5`) so all five tabs fit the 19rem pane and four fit the 320px phone panel; it scrolls sideways rather than wrapping if it outgrows its pane.

### The desktop workbench puts panes beside the call stage, never over it
`App.tsx` renders `Workbench.tsx` when `useMediaQuery(WORKBENCH_QUERY)` is true (`(min-width: 1024px) and (min-height: 501px)`) and the plain `Dialer` otherwise; `globals.css`'s `#root` cap stops at 1023px to match, and the `desk` screen in `tailwind.config.js` (`min-width: 640px and min-height: 501px`) is where the bar's panel buttons get labels (which is why the column is 40rem). The workbench is `AppBar` above a grid whose tracks come from the `workbench` utility: `var(--pane-left, minmax(19rem, 21rem)) minmax(22rem, 1fr) var(--pane-right, minmax(20rem, 24rem))`. The center's 22rem floor matters: grid sizing grows the side panes to their maximum before a `1fr` track gets anything, so with `minmax(0, 1fr)` a 1024px window would clip the Call button. `Pane.tsx` wraps each side pane (`role="region"`); its `PaneToggle` folds it to a 2.5rem rail by setting `--pane-left`/`--pane-right` inline (persisted in localStorage `dialer_workbench`), and the pane's children stay mounted under `hidden`. The center is `Dialer` unchanged, still the router to `CallScreen`/`IncomingCall`; it learns it is inside the workbench from `useWorkbench()` (no bar of its own, no overlays, History calls `openRecents()`, the keypad folds, stats go to `openCallStats()`). `useDialog` must never touch the panes: it moves focus inside and traps Tab, which would steal the address input's focus and with it Enter-to-dial in the field.

The Inspector's tabs are Quality (`CallStatsBody`), Events (`EventLog fill`), Devices (`DeviceSections` behind "Show devices", since it prompts for camera permission on mount, plus the audio-processing switches, disabled until a call is up because they act on `call.self`) and Diagnostics (session facts, `DoNotDisturbSwitch`, `SettingsBody`, `ConnectionTestBody`, `ExportDiagnosticsButton`, `SdkFacts`); Diagnostics is the default, and a call selects Quality, which stays selected after hangup. Every panel body is a named export the pane reuses. The Inspector keeps all four tab panels mounted and toggles `hidden`, so the connection test keeps its result and Quality keeps its last reading. `CallStatsBody` (re)subscribes on `callKey = connectedAt ?? (isInCall ? 0 : null)` (`isInCall` goes true before `dial()` has a Call, so the connect re-subscribes with the Call present) and on `null` unsubscribes without clearing, which is how the numbers survive hangup. The dial field (`phoneNumber`, `wantsVideo`, `picked`) lives in `hooks/useDialFieldStore.ts` so the Destinations pane, a sibling of the call stage, fills it through `selectAddress`. The phone's Call Statistics panel is `SheetShell` with `anchor="top" modal={false}` (no backdrop, `useDialog(..., { trapFocus: false })`) so Mute/End stay usable.

### The event log is the tester's timeline
`AppEvent` (`signalwire.ts`) is `{ at, kind: 'call' | 'media' | 'client' | 'error' | 'warning' | 'user', message, detail? }` in a `ReplaySubject(200)` exposed as `getEventLog$()`. `logEvent()` is called from the subscriptions and methods the service already has: token mint/refresh, `ready$` and `isRegistered$` (deduped; the initial `false` is not logged), client errors and warnings, device recovery, incoming calls, reattach adoption, `status$`, `call.errors$`, capability grants, `networkIssues$` (each issue once as it appears and once as it clears), screen share, recovery, media disruption, ICE state, and the user's actions. `handleCallEnded()` logs "Call ended" only while a call is still tracked, so the redundant end paths log once. `EventLog.tsx` subscribes directly, filters by kind, copies the visible lines as `ISO [kind] message — detail`, and "Clear" hides what was logged so far rather than emptying the shared buffer. The `events` spec feeds the private `logEvent()` directly.

### Address suggestions come from what the browser already has
`hooks/useAddressSuggestions.ts` merges Recents (`matchesRecent`) with the Directory pages the SDK has loaded (`matchesAddress`; both in `utils/search.ts`), six at most, deduped by path, minus your own address and the field's exact value. It subscribes to `directory.addresses$` only (subscribing to `hasMore$` triggers a fetch, and typing must not), so on phones the directory contributes once the Directory tab has been opened. `Dialer.tsx` owns the highlight and the keys: Up/Down cycle, Enter on a highlighted row picks (otherwise Enter in the field dials, through the field's own `onKeyDown`), Escape dismisses for the current value, and a pick dismisses until the field changes. The input is a `combobox` with `aria-activedescendant`; options swallow mousedown so the input keeps focus through a click.

### Backend "call tracking" is a log line
The frontend fires `POST /api/calls/dial` without awaiting it (awaiting it before `client.dial()` would leave a window where End is a no-op and the call is placed anyway). The endpoint validates and normalizes the destination, logs it and echoes a record back; nothing is stored. The real call log is the browser-side Recents store.

### Styling
The look follows the SignalWire docs. `globals.css` defines semantic color, font and radius tokens in `@theme` (the light values) and overrides them under `[data-theme='dark']`; Tailwind turns them into utilities (`bg-surface`, `text-muted`, `border-edge`, `bg-accent`, `font-display`, `font-mono`, `bg-switch-knob`, `bg-video`, …). Components use only those, so both themes come from one place; a color that is the same in both themes is still a token, repeated in the dark block. `services/theme.ts`'s `applyTheme()` resolves the Appearance setting (`system`, `light` or `dark`; default `dark`) to `data-theme` on `<html>` and keeps the theme-color metas in step. `main.tsx` calls it before the first render so the wrong theme never flashes, and the Appearance control calls it on change; it isn't part of `applySettings()`, which pushes SDK settings into the client. Tailwind scans source text, comments included, for class names, and the bare word `container` is one of its layout utilities, which breaks the build together with the raw `short` screen: hence the rule against the word (and names like `dialogEl`). The keypad is the `keypad-grid` utility with `key-button` keys, both in `globals.css`; the digit keeps the `dial-button-number` class, which the dialer spec reads.

## Conventions

- Backend request failures are described by `describeFetchError` in `services/api.ts` (429 rate limit, 401 key rejected, 503 unconfigured with the server's own message, 500 backend-side failure, 502/504/no response "Backend unreachable"); every list, the Subscriber panel and the startup error screen use it, and list errors offer Retry. Call failures are described by `describeCallError` in `useSignalWire.ts`, which reads the server's error code out of `CallCreateError`.
- App logging goes through `frontend/src/utils/log.ts`: `log.debug`/`log.info` print only when "App debug logs" is on, `log.warn`/`log.error` always. The SDK's own logging is the separate `logLevel` setting.
- Phone numbers: frontend and backend both normalize to E.164 (`+1` prefix for 10-digit US numbers; a number typed with a leading `+` keeps its digits), stripping formatting characters first. `signalwire.ts:normalizeDestination` (shared by `makeCall` and `transferCall`) and `utils/signalwire.py:format_phone_number` do this; keep them in sync and update `frontend/e2e/fixtures/dial-normalization.json`, which both suites read. `Dialer.tsx`'s 7-digit minimum counts digits only (`countDigits`).
- Dial-address detection is duplicated, deliberately: SIP URIs (`sip:...` or anything containing `@`) and Fabric addresses (paths starting with `/`) bypass E.164 normalization, checked by `SignalWireClient.is_dial_address` (backend) and `isDialAddress` in `utils/address.ts` (frontend). Same sync rule.
- Line endings are mixed and there's no `.gitattributes`. CRLF: the original files — `signalwire.ts`, `api.ts`, `tones.ts`, `useSignalWire.ts`, `useCallStore.ts`, `Dialer.tsx`, `DialPad.tsx`, `CallScreen.tsx`, `IncomingCall.tsx`, `ErrorBoundary.tsx`, `App.tsx`, `main.tsx`, `types/index.ts`, `globals.css`, `index.html`, `package.json`, the Vite/Tailwind/PostCSS/tsconfig/eslint configs, and `backend/app.py`, `api/auth.py`, `api/calls.py`, `utils/signalwire.py`, `requirements.txt`. Every other file is LF, including the docs and `.env.example`. Preserve each file's endings; a text-mode rewrite turns a small edit into a whole-file diff.
- The repo is public. `README.md` is for SignalWire customers (setup, usage, the SDK-feature-to-file map). The README, code comments and commit messages never point to this file. This file describes how the app works and what to preserve, in neutral terms. When behavior changes, update the README's feature map or usage if a customer would notice.
